# 콘텐츠 가이드

무엇을 쓰고, 어떤 형식으로, 어떤 목소리로 쓰는지를 정한다. 발행 절차는 `PUBLISHING.md`에 있다.

## 사이트가 말하려는 것

실제 공간과 디지털 공간을 잇는 문제를 의료와 로보틱스에서 다루는 연구자의 기록이다.
중심 질문은 정합이다. 영상, 센서, 환자, 도구가 각자의 좌표계에 있을 때 이들을 하나의 공간으로 묶고, 대상이 움직여도 그 관계를 유지하는 방법을 다룬다.

사이트 태그라인은 `Surgical Navigation · Spatial AI · 3D Vision · Registration · Robotics`다. `_config.yml`의 `tagline`과 같게 유지한다.

독자는 세 부류로 본다.

| 독자 | 사이트에서 찾는 것 |
|---|---|
| 같은 분야의 연구자와 교수 | 어떤 문제를 어떤 수준으로 이해하고 있는가 |
| 산업계 개발자 | 구현 과정과 시행착오 |
| 진학·협업을 검토하는 사람 | 무엇을 직접 했고, 기여가 어디까지인가 |

## 글 유형

| 유형 | 쓰는 때 | 분량 기준 |
|---|---|---|
| Research Note | 하나의 연구 질문을 정리할 때 | 길다 |
| Paper Review | 논문 한 편을 읽고 자기 연구와 잇는 때 | 중간 |
| Technical Deep Dive | 개념이나 알고리즘 하나를 수식·코드로 풀 때 | 길다 |
| Implementation Note | 직접 구현하며 겪은 문제와 해결 | 중간 |
| Development Log | 프로젝트의 날짜별 진행 기록 | 짧다 |
| Research Journey | 경험과 그것이 연구 방향에 준 영향 | 중간 |
| Project Case Study | 프로젝트 하나를 독립된 결과물로 소개 | 프로젝트 페이지 |

분량은 기준일 뿐이다. 할 말이 끝나면 글도 끝낸다.

## 시리즈

- 하나의 주제를 여러 편으로 나눌 때 쓴다. 글의 front matter에 시리즈 이름과 순번을 적는다.
- 목록, "N편 중 M편" 표시, 이전·다음 연결은 front matter에서 만든다. 번호를 본문이나 다른 페이지에 손으로 적지 않는다.
- 아직 쓰지 않은 편을 목록에 올릴 때는 "준비 중"이라고 표시한다. 발행 날짜는 약속하지 않는다.
- 연구 기록 시리즈는 게시일과 별도로 작업 시기를 적는다.

## 템플릿

아래 구성은 출발점이다. 글에 맞지 않는 항목은 뺀다. 모든 글에 같은 틀을 강제하지 않는다.

2. 배경과 문제 정의
3. 관련 개념
4. 접근 방법과 그것을 고른 이유
5. 내가 이해한 것: 출처의 내용과 구분해서
6. 그림과 예시
7. 남은 문제
8. 다음에 볼 것
9. 참고문헌

### Paper Review

1. 논문 정보: 저자, 발표처, 연도, DOI
2. 연구 문제
3. 기존 방법의 한계
4. 핵심 아이디어
5. 방법
6. 주요 실험 결과: 논문의 수치는 표나 그림 번호와 함께 인용
7. 논문의 한계
8. 내 해석
9. 내 연구와의 연결
10. 이어지는 질문

### Project Case Study

1. Problem
2. Motivation
3. Approach
4. System Architecture
5. Implementation
6. Demo

8. Limitations
9. My Contributions: 공동 작업에서 내가 한 부분
10. What's Next: 상태 표시와 함께

### Development Log

1. 날짜와 프로젝트
2. 풀려던 문제
3. 한 일
4. 생긴 문제
5. 해결 과정: 원인을 구체적으로
6. 검증 결과: 전과 후
7. 남은 일
8. 그림, 코드, 자료

### Research Journey

1. 경험이나 사건
2. 그때의 고민
3. 배운 것
4. 연구 방향에 준 영향
5. 앞으로의 목표

## 결과를 적는 방식

- 수치에는 조건을 붙인다. 시뮬레이션, 팬텀, 벤치, 실제 환경 가운데 무엇인지 적는다.
- 프로젝트의 앞으로 할 일은 날짜가 아니라 상태로 적는다. `검증됨`, `진행 중`, `탐색 중`, `구상 단계`를 쓴다.
- 근거 링크는 검증된 결과에만 단다. 계획에는 아직 확인하지 못한 것을 함께 적는다.
- 실패한 시도도 기록한다. 시도, 원인, 수정, 남은 한계의 순서로 쓴다.
- 공개할 수 없는 근거는 지어내거나 흐리게 쓰지 않고, 다루지 않는다고 밝힌다.

## 문체

- 평서문 "~다"체로 쓴다. 1인칭은 "나"를 쓴다.
- 질문이나 구체적인 문제에서 시작한다. 배경 설명으로 문을 열지 않는다.
- 한 문단은 하나의 주장만 담는다.
- 확인한 사실과 내 해석을 문장 단위로 구분한다. "논문은 ~라고 보고한다"와 "나는 ~라고 본다"를 섞지 않는다.
- 전문 용어는 분야에서 쓰는 표기를 따른다. 처음 나올 때 한 번 풀어 쓴다.
- 과장하는 수식어, 같은 구조의 문장 반복, 홍보 문구를 쓰지 않는다.
- 아직 갖추지 못한 전문성을 가진 것처럼 쓰지 않는다. 공부하는 중이면 그렇게 적는다.

## 영어판

- 영어판은 번역이 아니라 같은 내용을 영어로 다시 쓴 글이다. 구조와 그림, 수식은 같게 둔다.
- 용어는 해당 분야 논문에서 쓰는 표현을 따른다.
- 영어판을 먼저 만들 대상은 Home, About, 대표 프로젝트, 대표 연구 노트다. 모든 글을 번역하지 않는다.
- 한국어판을 고치면 영어판의 갱신 여부를 front matter에 표시한다.

## 그림과 인용

- 그림은 직접 그린 것을 먼저 쓴다. 논문 그림을 옮길 때는 출처와 사용 조건을 캡션에 적는다.
- 파일은 글별 폴더에 두고 이름에 내용을 적는다.
- 모든 그림에 대체 텍스트와 캡션을 단다.
- 참고문헌은 글 끝에 번호 목록으로 두고 DOI나 공식 링크를 붙인다.
